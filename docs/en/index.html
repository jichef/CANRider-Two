CanRider · installation guide

From ESP32 box to live map

Everything you need to get your electric motorcycle sending real CAN telemetry to your own web dashboard: database, portal, firmware and wiring — explained step by step, assuming no prior knowledge.

CAN → ESP32 → LTE → Supabase → web portal (+ Home Assistant if you want)

What the firmware does

  • Reads and decodes the CAN bus of the bike — up to 32 configurable signals (frame + byte + scale + sign), with individual bit extraction (flags) and "dual mode" to listen to two frame IDs with a single signal
  • Only ever transmits the clock to the bike's dashboard, never anything else — adding any new transmitted frame requires editing the firmware itself, editing config.h alone is not enough, by design
  • Recovers on its own from a bus-off (the CAN controller disconnecting from the bus due to errors) without needing to manually reset the ESP32
  • GPS positioning, with cell-tower triangulation (LBS) as a fallback when there's no satellite coverage — every reading indicates which source it came from
  • Network time with the correct time zone (taken from the carrier, corrects for daylight saving) — and doesn't transmit the time over CAN until it's valid, so it never sends a clock full of garbage data
  • Sends telemetry every 15 seconds to Supabase: position, speed, the ESP32's own battery, signal strength, and every CAN signal it read
  • Detects the start and end of each trip from the CAN bus itself — bike on = frames on the bus, bike off = silence — instead of from GPS speed; it stores distance, top speed, duration and battery used
  • Flags movement without CAN: if the GPS measures real movement while the CAN bus has been silent for several seconds (bike off), it's flagged as possible theft — the bike doesn't move on its own while switched off
  • Handles unstable roaming — retries with backoff between failures and a full network reconnect after consecutive failures, instead of hammering the carrier's network
  • Two boards supported — LilyGo T-SIM7000G and T-A7670G — with the pins for each already sorted out: just pick which one you have in config.h
  • Optional OTA update — advertises low-power Bluetooth; connecting from your phone (no app needed) while the bike is off brings up its own WiFi with a page to upload new firmware, no cable or Arduino IDE required

What you'll need before you start

  • LilyGo T-SIM7000G board (official store, recommended, the most tested one in this project) or T-A7670G (official store — pick the "A7670G" variant in the dropdown, not the E or SA) — both have LTE + GPS built in and the firmware supports both, see step 6. Both are also available on AliExpress, usually cheaper
  • CAN transceiver (SN65HVD230, TJA1050 or similar) at 3.3V — example SN65HVD230 module
  • SIM card with a data plan active, with the PIN disabled
  • USB cable that carries data (not charge-only) for the board
  • 18650 battery as a power backup (recommended, not required)
  • High-voltage-to-USB DC-DC converter (rated for your bike's battery voltage — electric bikes typically run 48V to 72V) to power the ESP32 straight from the bike instead of relying only on the 18650 — example: 8-85V DC to 5V/3A USB converter
  • Access to the bike's CAN bus — CAN-H and CAN-L (the transceiver already includes the 120 Ω termination resistor, no need to add one separately)
  • A GitHub, Supabase and Vercel account — all three are free
STEP 01

Create the Supabase project

Supabase is the cloud database where all of your bike's telemetry will live.

  1. Go to supabase.com and click Start your project. Sign up with GitHub, it's the quickest way.
  2. Click New project. Pick a name (for example canrider), a database password (save it somewhere safe) and a region close to you.
  3. Wait 1-2 minutes while Supabase provisions the project.
Tip

The database password it asks for here is not the key the ESP32 will use — we'll get that later. You can save it and forget about it.

STEP 02

Create the tables (the database "dump")

We're going to give Supabase the database structure: what tables exist and what each one stores. You don't need to understand the code — just copy some text and paste it in the right place, exactly as it is, without changing anything.

First, clone or download the project repository to your computer (if you already did, skip to the next point):

terminal
git clone https://github.com/jichef/CANRider-Two.git
Not using the terminal?

On the repository's GitHub page, click the green Code → Download ZIP button, unzip the file on your computer, and use that folder instead of cloning via commands.

Now it's time to copy over the database "template". Follow these steps in exactly this order:

  1. On your computer, inside the project folder, open the file supabase/schema.sql with any text editor (Windows Notepad, Mac TextEdit, or VS Code itself all work).
  2. Select the entire contents of the file: click inside the text and press Ctrl+A (Windows) or Cmd+A (Mac). Then copy it with Ctrl+C / Cmd+C.
  3. Go to the browser tab where you have your project open at supabase.com.
  4. In the left menu, find the icon with the </> symbol — it's called SQL Editor — and click it.
  5. At the top left of that screen, click the + New query button.
  6. Click inside the big dark box that takes up the center of the screen, and paste the text you copied: Ctrl+V / Cmd+V.
  7. Click the green Run button (bottom right of the box).
How do I know it worked?

At the very bottom a green message will appear, something like Success. No rows returned. That's good: it means the three tables were created without errors.

To check it with your own eyes: in the left menu click the Table Editor icon (looks like a table/spreadsheet). You should see three new tables in the list: can_signals, telemetry and trips.

If a red message shows up

It usually means the text got pasted incomplete (for example, if the file wasn't fully selected). Clear everything in the SQL Editor box, copy the whole file again from step 1, and paste it once more.

Finally, generate a unique identifier for your bike. In the same SQL Editor, click + New query again, paste this and click Run:

sql
select gen_random_uuid();

This time, instead of a green message, a table will show up with a single result: a long code with dashes, something like 3fa85f64-5717-4562-b3fc-2c963f66afa6. Copy it and save it somewhere (a note, a document) — it's your VEHICLE_ID.

✓ That code is your VEHICLE_ID — you'll need it in step 6 and step 4.
STEP 03

Copy the URL and the key

Two pieces of data you'll paste in a few more places later — worth having them handy now.

In Supabase, go to Project Settings → API and copy:

  • Project URL — something like https://xxxxxxxx.supabase.co
  • anon public key — a long string starting with eyJ...
Warning

On that same screen you'll see another key called service_role key. That one is full admin access and must never go into the firmware, the web portal, or anywhere public. Always use the anon key.

STEP 04

Deploy the web portal

Vercel builds and hosts the website automatically every time you update the GitHub repository.

  1. Push the project to your own GitHub repository (or fork this one).
  2. Go to vercel.com, sign in with GitHub and click Add New → Project.
  3. Pick your repository and click Import.
  4. Before hitting Deploy, expand Environment Variables and add these three:
VariableValue
NEXT_PUBLIC_SUPABASE_URLyour Project URL from step 3
NEXT_PUBLIC_SUPABASE_ANON_KEYyour anon key from step 3
NEXT_PUBLIC_VEHICLE_IDthe UUID you generated in step 2

Click Deploy and wait a couple of minutes. When it's done you'll have a public URL like your-project.vercel.app with the dashboard — still with no data, though, since the bike hasn't sent anything yet.

Note

If you change an environment variable in Vercel later, it doesn't apply on its own — go to Deployments and click Redeploy on the latest deployment.

STEP 05

Set up Arduino IDE

Install ESP32 support and the modem library, just once.

  1. Download and install Arduino IDE 2.x.
  2. Go to Arduino IDE → Preferences and paste this into Additional boards manager URLs:
url
https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
  1. Go to Tools → Board → Boards Manager, search for esp32 and install the Espressif package.
  2. Select the board: Tools → Board → ESP32 Arduino → ESP32 Dev Module.
  3. Go to Tools → Partition Scheme and pick "Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)" instead of the default one.
  4. Go to Tools → Manage Libraries, search for TinyGSM and install it.
Why change the partition scheme?

The default one only leaves 1.2 MB for the firmware — plenty for the normal firmware, but not for the optional OTA update feature (BLE + WiFi take up a fair amount of flash). Changing it now, even if you're not going to use OTA, avoids a confusing compile error later if you ever turn it on.

STEP 06

Create and edit config.h

The only firmware file that needs your data — everything else is already set up.

Inside the project's main/ folder there's a file called config.h.example. Rename that example file to config.h (dropping the .example at the end) — that's the file you'll fill in with your data, and the one the firmware reads when compiling.

terminal
cp main/config.h.example main/config.h
Not using the terminal? Do it by hand

Open the main/ folder with your system's file browser (Finder on Mac, File Explorer on Windows). Find the file config.h.example, copy it and paste it in the same folder (so you'll have two copies), and rename the new copy to config.h — dropping the .example at the end. Leave the original config.h.example as it is, don't delete it.

Important

Always edit config.h (the one you just created), never config.h.example. That original file isn't even pushed to git — it's just the reference template everyone starts from.

Open main/config.h with any text editor. Inside it's split into five blocks literally marked with >>> CHANGE THIS <<< (in Spanish in the file: CAMBIA ESTO). Fill these in for your case and don't touch the rest of the file:

main/config.h
// 1/5 — which board you have: uncomment ONLY the line for your board
// (remove the "//" in front of it) and leave the other one commented
// out. Both start commented out on purpose — you have to choose,
// there's no board active by default.
// #define MODEM_A7670G
// #define MODEM_SIM7000G

// 2/5 — your Supabase and bike details (step 3 and step 2 of this guide)
#define SUPABASE_URL "https://xxxxxxxx.supabase.co"
#define SUPABASE_KEY "eyJ..."
#define VEHICLE_ID   "the-code-you-saved-in-step-2"

// 3/5 — your carrier's APN (ask them, or look it up as
// "M2M/IoT APN <your carrier>")
#define APN "internet.yourcarrier.com"

// 4/5 — only if your bike's bus doesn't run at 250 kbps
#define CAN_SPEED TWAI_TIMING_CONFIG_250KBITS()

// 5/5 — which CAN frame (frame ID) and byte each piece of data lives
// in. There are only 5 signals: the clock sent to the dashboard
// (nothing else is ever sent over CAN), the two batteries' %, and
// whether it's charging.
//
// These lines start commented out on purpose. Do NOT uncomment them
// with made-up values or values copied from another bike: find your
// own with a CAN analyzer or the manufacturer's documentation first.
//
// Format: frame ID in hex (0x...), byte 0 to 7 within the frame.
// CAN_CHARGING_BITMASK is different: it's not a whole byte, it's one
// bit within that byte (0x10 = bit 4) — the firmware checks
// data[byte] & bitmask and stores 1 if that bit is set.
//
// Here's what an EXAMPLE would look like (don't copy it, it's not real):
//   #define CAN_CLOCK_FRAME     0x200
//   #define CAN_CLOCK_HOUR_BYTE 0
// #define CAN_CLOCK_FRAME
// #define CAN_CLOCK_HOUR_BYTE
// #define CAN_CLOCK_MIN_BYTE

// #define CAN_BATTERY_A_FRAME
// #define CAN_BATTERY_A_BYTE

// #define CAN_BATTERY_B_FRAME
// #define CAN_BATTERY_B_BYTE

// #define CAN_CHARGING_FRAME
// #define CAN_CHARGING_BYTE
// #define CAN_CHARGING_BITMASK
What if I don't know my bike's values yet?

You can still flash it leaving block 5/5 as-is (commented out). Each signal is independent: if you leave the clock unconfigured, the firmware won't transmit any frame over CAN; if you leave a battery or the charging status unconfigured, it simply won't show that data in the portal — you don't need to fill in all five at once. Everything else (GPS, LTE, web portal) works the same. In the Serial Monitor from step 9 you'll see [CAN] 0 signals while it's all commented out — that's normal.

Once you do know the values

For each signal you want to enable, uncomment and fill in all of its lines together — if a signal is missing one piece of data (say, the byte but not the frame), that whole signal gets ignored. Never copy the example values or another bike's values: mistakenly sending a frame with the wrong frame ID or content to a real CAN bus can cause unexpected behavior in the vehicle.

What if my bike has more signals than these five?

Block 5/5 of config.h is all you need to adapt the clock, both batteries and the charging status to your bike — no other file needs touching for that.

Only if you need to read some additional CAN signal, or send some new frame on the bus, do you need to edit the setupCANSignals() function inside main/main.ino directly. That's by design: it means what the ESP32 transmits over CAN can never be expanded just by touching a config file — any new outgoing frame requires touching the code itself.

STEP 07

Wire up the CAN bus

Four wires between the ESP32 and the transceiver, plus the two from the bus itself.

SignalT-SIM7000GT-A7670GCAN transceiver
CAN TXGPIO 32GPIO 22CTX / TXD
CAN RXGPIO 33GPIO 21CRX / RXD
Power3.3V3.3VVCC
GroundGNDGNDGND
Different boards, different pins

Use the column for your board. On the T-A7670G, GPIO 33 is avoided on purpose because the modem uses it internally (RING pin) — that's why that board uses GPIO 22/21 instead of 32/33. These are the same pins already set in block 4/5 of config.h (CAN_TX_PIN / CAN_RX_PIN) based on the board you picked in block 1/5 — no need to change them by hand.

If your transceiver has a 3V3-STDBY pin or similar, connect it to 3.3V too so it starts up in normal active mode. Insert the SIM into the modem with the board powered off, and connect the LTE antenna and the GPS antenna to their connectors (they're different, don't mix them up).

Where do I get power and the CAN-H/CAN-L lines from?

The ESP32 isn't powered from the transceiver's 3.3V (that's only the transceiver's own logic supply) — it needs 5V over USB, which is what the DC-DC converter from the list above, connected to the bike's main battery, is for.

A common spot to grab power and both CAN lines at once is the vehicle's original ECU connector: many ECUs have battery voltage, GND and the CAN-H/CAN-L bus already present there. Locate your ECU's connector, identify those pins with a multimeter or your vehicle's diagram, and tap the DC-DC converter and transceiver in there instead of splicing loose wires into the chassis.

Before touching the ECU

Disconnect the bike's battery before working on the ECU connector. If you're going to remove or disable the original ECU to access its connector, keep in mind that this can disable whatever that ECU used to control — make sure that's what you want before cutting anything. Remember the legal notice at the top of this guide: you do this at your own responsibility.

STEP 08

Flash the firmware to the board

With everything wired up and the SIM in place, it's ready to flash.

  1. Open main/main.ino in Arduino IDE (it will also open config.h, structs.h, StreamDebugger.h and the rest of the project's tabs).
  2. Connect the board to your computer over USB.
  3. Select the port under Tools → Port.
  4. Click Upload (or Ctrl+U / Cmd+U).
About the StreamDebugger.h tab

You'll see an extra tab called StreamDebugger.h — it's already included inside the repository's main/ folder, no need to install it or copy it anywhere. The TinyGSM library from step 5 does need installing from the Library Manager as explained there; this tab is just a small separate helper that's already ready to go.

If it doesn't connect

Some boards with unreliable auto-reset need manual entry into bootloader mode: hold down BOOT, tap RESET once without releasing BOOT, and release BOOT right before clicking Upload.

STEP 09

Check it's working

Open the Serial Monitor (115200 baud) and watch it boot live.

A healthy boot looks like this, roughly in this order:

serial monitor · 115200
[CAN] TWAI listo
[CAN] 5 señales (1 frames TX)
[STATE] NET_SETUP...
[STATE] HTTP_SETUP...
[TIME] UTC: 2026-08-31 12:03:41
[STATE] RUNNING
[POST] {"motorcycle_id":"...","moto_battery_b":54,...}
[OK] Telemetría enviada

Those log lines print in Spanish regardless of which language you're reading this guide in — that's just how the firmware's own debug output is written, it doesn't affect anything functional. [CAN] TWAI listo means "TWAI ready", [CAN] 5 señales means "5 signals", and [OK] Telemetría enviada means "Telemetry sent".

As soon as you see [OK] Telemetría enviada at least once, open your portal's URL on Vercel — the first data points should already be showing up.

✓ If you see that, your CanRider is working end to end.
EXTRA

Home Assistant (optional)

If you already run Home Assistant, you can bring in the bike's data like any other device.

  1. Copy the custom_components/can_rider folder from the repository to config/custom_components/ in your Home Assistant install.
  2. Restart Home Assistant.
  3. Go to Settings → Devices & Services → Add Integration and search for CanRider.
  4. Fill in your Supabase URL and anon key, the VEHICLE_ID, and the board model.

You'll get sensors for the bike's Battery A and B, charging status, ESP32 battery, speed, signal strength, GPS tracking, last-trip data, and a "movement without CAN" binary sensor so you can build your own alert (a phone notification, a siren...) if the bike moves while switched off.

IF SOMETHING GOES WRONG

Troubleshooting

The ESP32 doesn't connect to the network

  • Check that the APN in config.h matches your carrier's exactly
  • Confirm the SIM has an active data plan and doesn't ask for a PIN
  • Look for [ERROR] or [TIMEOUT] in the Serial Monitor

No data shows up in the portal

  • Check the three environment variables in Vercel (step 4) and hit Redeploy if you just changed them
  • Confirm the VEHICLE_ID is identical in config.h and in Vercel

GPS can't get a fix

  • Check that the GPS antenna is in its own connector (not the LTE one)
  • It can take several minutes outdoors the first time
  • In the meantime, the firmware automatically tries an approximate position via cell-tower triangulation (LBS)

CAN signals aren't coming through

  • Check CAN_SPEED in config.h against your bike's actual bus speed
  • Check the wiring from step 7
  • Check that you've uncommented and filled in block 5/5 of config.h — if you left it as it came, the firmware doesn't transmit or read any signal (you'll see this in the Serial Monitor as [CAN] 0 señales)
  • If you see [CAN] Bus-off detectado, the firmware recovers from it on its own — if it keeps happening, check the bus termination

Compile error: "text section exceeds available space"

  • You've enabled OTA_AP_PASSWORD in config.h but you're still on the default partition scheme — go to Tools → Partition Scheme and pick "Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)" (see step 5), then compile again
